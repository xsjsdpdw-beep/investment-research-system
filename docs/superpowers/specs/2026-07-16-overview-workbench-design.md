# 行业/个股概览工作台设计稿

日期：2026-07-16

## 1. 目标

为 `框架沉淀 -> 行业中心` 与 `框架沉淀 -> 个股中心` 的 `行业概览 / 个股概览` 建立统一的工作台结构，使其不再只是单次生成的静态内容，而是成为一个可持续迭代的研究底座。

该工作台要同时满足四个目标：

1. 能通过“提取研报”快速生成一个可用的初始框架。
2. 能把用户后续投喂的研报、附件、纪要、专家会内容沉淀为长期版本。
3. 能让新增材料先进入缓冲区，而不是直接覆盖用户的主判断。
4. 能以正式主版本为基础，一键生成高质量行业报告或个股报告。

## 2. 适用范围

本设计同时适用于两类对象：

1. 行业中心中的 `行业概览`
2. 个股中心中的 `个股概览`

两者共用同一套页面结构、数据模型、候选吸收机制和版本留痕机制，仅在默认卡片模板、报告文案和引用来源名称上有所区分。

## 3. 页面结构

`行业概览` 与 `个股概览` 顶部统一采用 4 个 tab 切换：

1. `初稿`
2. `深度`
3. `待吸收`
4. `生成报告`

这 4 个 tab 的职责如下。

### 3.1 初稿

`初稿` 是自动生成区，用于承接“提取研报”或后续自动抓取资料后的第一版框架。

定位：

1. 快速起框架
2. 展示自动抽取结果
3. 持续刷新，但不直接影响用户主版本

页面内容：

1. 顶部工具区
   - `提取研报`
   - `重新生成初稿`
   - `查看自动信息源`
2. 初稿摘要区
   - 最近一次生成时间
   - 本次读取资料数量
   - 本次命中的关键词/主题
3. 初稿内容区
   - 以卡片形式展示自动生成的模块
   - 每张卡片对应一个概览模块，如市场规模、产业链、竞争格局等
4. 卡片操作
   - `加入待吸收`
   - `忽略`
   - `查看来源`

说明：

1. `初稿` 允许持续更新。
2. `初稿` 不得直接改写 `深度`。
3. 每次更新初稿后，仅形成新的候选增量，不自动同步到主版本。

### 3.2 深度

`深度` 是用户的正式主版本，采用卡片库而不是长文模式。

定位：

1. 承载用户长期维护的正式研究框架
2. 允许 AI 参与整理，但不允许自动覆盖
3. 作为最终生成报告的主输入

页面内容：

1. 顶部工具区
   - `新增卡片`
   - `从多篇资料导入`
   - `未分类检查页`
   - `查看版本记录`
2. 深度卡片区
   - 每张卡片可折叠
   - 折叠态只显示标题、前 2-3 行正文预览、最近更新时间、待吸收状态
   - 展开后显示完整正文、图片区、图表区、来源区、版本留痕
3. 卡片附属区
   - 来源引用
   - 最近更新时间
   - 最近一次吸收来源
   - 版本数量

默认卡片模板：

行业概览默认建议包含但不限于：

1. 市场规模与需求
2. 产业链结构
3. 竞争格局
4. 核心公司
5. 行业驱动因素
6. 催化剂
7. 风险点
8. 自定义卡片

个股概览默认建议包含但不限于：

1. 公司定位与业务结构
2. 成长逻辑
3. 竞争优势
4. 管理层与治理
5. 财务与经营抓手
6. 催化剂
7. 风险点
8. 自定义卡片

说明：

1. `深度` 的每张卡片都是正式内容。
2. 深度卡片默认是只读，不允许直接在阅读态随手改写。
3. 每个区块单独有 `编辑` 入口，分别保存、分别取消，不共享脏状态。
4. 用户可以手动编辑，后续也可接入 AI 辅助润色。
5. 任何自动更新内容都不能直接进入正式卡片。

### 3.3 待吸收

`待吸收` 是所有新增信息的缓冲区，是本设计的核心。

定位：

1. 承接新增材料的结构化提炼结果
2. 让用户在吸收前先看差异
3. 避免初稿、附件、纪要等内容直接污染主版本

页面内容：

1. 顶部筛选区
   - 按来源筛选
   - 按日期筛选
   - 按状态筛选
2. 候选分组区
   - `研报`
   - `附件`
   - `纪要`
   - `专家会`
3. 候选列表
   - 每条候选项显示标题、来源、命中卡片、目标区块、摘要、生成时间
4. 候选操作
   - `对比后决定`
   - `忽略`
   - `标记稍后处理`

来源约束：

1. 自动提取的公开研报进入 `研报`
2. 用户在附件链接中上传或粘贴的新资料，解析后进入 `附件`
3. 调研纪要解析结果进入 `纪要`
4. 专家会纪要解析结果进入 `专家会`
5. 数据图表块自动更新后产生的观点候选进入对应来源分组，并挂接命中的深度卡片

候选状态：

1. `未处理`
2. `已吸收`
3. `已忽略`
4. `稍后处理`

### 3.4 生成报告

`生成报告` 是输出页，不承担编辑和沉淀职责。

定位：

1. 将概览工作台中的成熟内容整理为报告
2. 支持行业报告、个股报告的统一生成
3. 支持选择输入源范围

页面内容：

1. 报告类型
   - 行业报告
   - 个股报告
2. 输入源选择
   - `仅深度`
   - `深度 + 待吸收`
   - `初稿 + 深度`
3. 报告风格选择
   - 深度版
   - 快速版
   - 汇报版
4. 输出动作
   - `生成报告`
   - `生成图片`
   - `复制摘要`

说明：

1. 默认推荐输入源为 `仅深度`。
2. 若用户选择包含 `待吸收`，应在生成前给出提示，说明报告可能包含未正式确认的信息。

## 4. 深度卡片数据模型

每张深度卡片都应具备以下 4 层结构：

1. `正式内容`
2. `候选变更`
3. `版本记录`
4. `来源引用`

### 4.1 正式内容

正式内容是当前可见、可编辑、可用于生成报告的主版本。

字段建议：

1. `id`
2. `scope_type`：`sector` 或 `stock`
3. `scope_id`
4. `title`
5. `body`
6. `preview_text`
7. `image_blocks`
8. `chart_blocks`
9. `source_blocks`
10. `status`
11. `updated_at`

每张深度卡片在页面中的展示规则：

1. 默认折叠
2. 折叠态显示标题与前 2-3 行正文预览
3. 展开后内容按固定顺序纵向排列：
   - 完整正文
   - 图片区
   - 图表区
   - 来源区
   - 版本留痕

每个区块都必须独立编辑：

1. `正文区编辑`
2. `图片区编辑`
3. `图表区编辑`
4. `来源区编辑`

编辑规则：

1. 区块默认只读
2. 点击该区块自己的 `编辑` 才进入编辑态
3. 该区块单独 `保存 / 取消`
4. 未保存退出时要提醒用户是否放弃修改

### 4.2 候选变更

候选变更来自 `待吸收`，但命中的是某张已有卡片。

字段建议：

1. `candidate_id`
2. `source_type`
3. `source_title`
4. `source_url`
5. `proposed_patch`
6. `matched_card_id`
7. `target_block`
8. `created_at`
9. `state`

其中 `target_block` 必须明确候选落到卡片的哪个区块：

1. `body`
2. `image`
3. `chart`
4. `source`

### 4.3 版本记录

每次用户确认吸收某条候选后，都要生成一条版本留痕。

字段建议：

1. `version_id`
2. `card_id`
3. `action_type`
4. `source_type`
5. `source_title`
6. `before_snapshot`
7. `after_snapshot`
8. `change_summary`
9. `created_at`

### 4.4 来源引用

来源引用用于说明一张卡片当前判断背后的材料来源，不等同于附件区展示。

来源只展示自动提取来源与后续可接入来源，例如：

1. 东财研报
2. AlphaEngine
3. 公开纪要接口
4. 专家会接口

用户手动上传的文件与笔记链接继续保留在 `附件链接` 模块，不在这里直接展示为信息源接口。

## 5. 候选吸收机制

候选项进入 `待吸收` 后，不允许直接写入 `深度`。

标准流程：

1. 新材料进入系统
2. 系统提炼出候选项
3. 候选项按来源进入 `待吸收`
4. 若命中已有卡片，则进入 `对比后决定`
5. 用户确认后，系统再写入正式卡片并保留版本记录

用户确认动作只支持以下几类：

1. `替换原文`
2. `追加为补充段`
3. `仅更新局部`
4. `忽略`

不提供自动覆盖。

新增约束：

1. 若候选项来自数据图表块的自动更新，系统先更新图表，再生成观点候选进入 `待吸收`
2. 图表更新不得直接改写正文
3. 候选吸收时必须保留该候选原始来源与区块归属

## 6. 对比视图设计

当候选项命中已有卡片时，系统默认进入 `对比后再决定` 模式。

交互要求：

1. 左侧显示 `原有版本`
2. 右侧显示 `候选新内容`
3. 中间高亮差异
   - 新增内容
   - 删除内容
   - 改写内容
4. 底部显示操作按钮
   - `替换原文`
   - `追加补充`
   - `仅更新选中段落`
   - `忽略`

目标：

1. 用户能清楚知道改了什么
2. 用户能基于差异做判断
3. 吸收后能完整留痕

## 7. 版本留痕设计

版本留痕用于支持未来复盘观点演化。

每条版本记录至少展示：

1. 日期时间
2. 来源类别
3. 来源标题
4. 命中的卡片
5. 改动摘要
6. `查看变更前后`

复盘时，用户应能看到：

1. 原来怎么写
2. 后来因什么材料做了修改
3. 具体改动点是什么

## 8. 与现有模块的关系

### 8.1 附件链接

`附件链接` 保持为手动资料库，仅展示用户主动上传或粘贴的资料。

新增要求：

1. 新增附件进入资料库后，可以触发解析
2. 解析结果不直接进入 `深度`
3. 解析结果进入 `待吸收 -> 附件`

对于无法通过公开研报提取形成有效初稿的行业或个股，允许用户直接通过 `附件链接`、有道云笔记、纪要等资料在 `深度` 中搭建框架，不依赖初稿先存在。

### 8.2 调研纪要 / 行业纪要 / 跟踪点评

这些内容依旧保留在行业中心、个股中心的原模块中。

新增要求：

1. 新写入的纪要或点评可以触发候选提炼
2. 候选结果进入 `待吸收`
3. 若命中某张概览卡片，则支持差异对比吸收

### 8.3 信息源接口

`行业概览 / 个股概览` 下方保留与 `投研资讯` 类似的信息源展示与扩展接口。

但只展示自动提取来源和未来的外部接口来源，不展示用户手动投喂资料。

### 8.4 多资料导入与未分类检查页

`深度` 顶部提供 `从多篇资料导入` 入口，支持一次导入多篇资料：

1. 有道云笔记
2. 附件链接
3. 调研纪要
4. 专家会纪要

导入流程必须固定为：

1. 多篇资料进入系统
2. 进入 `未分类检查页`
3. 系统预判每条资料应归属的卡片与区块
4. 用户批量或逐条修正
5. 直接分发到对应卡片的候选池

不允许直接跳过 `未分类检查页` 自动写入正式深度卡片。

未分类检查页要求：

1. 每条资料显示标题、来源、2-3 行内容预览
2. 显示系统建议卡片
3. 显示系统建议区块：`正文 / 图片 / 图表 / 来源`
4. 支持批量分发
5. 支持逐条改目标卡片与目标区块
6. 支持 `新建卡片后分发`
7. 支持 `暂存未分类`

批量分发规则：

1. 默认支持 `按系统建议批量分发`
2. 分发后直接进入对应卡片的候选池
3. 不增加额外确认批次页

候选落点规则：

1. 文字内容进入 `正文候选`
2. 图片/截图进入 `图片区候选`
3. 指标/数据进入 `图表区候选`
4. 链接/出处进入 `来源区候选`

### 8.5 数据库图表块

数据库中的可跟踪指标，不应只停留在数据库模块，而应能反向挂接到行业概览和个股概览的深度卡片中，作为 `数据图表块`。

数据图表块分为：

1. `当前图表`
2. `指标配置`
3. `变化留痕`
4. `历史快照`

工作规则：

1. 图表默认自动随数据库更新
2. 每次更新必须留痕
3. 每次更新后自动生成一条 `待吸收候选观点`
4. 图表留痕与卡片版本留痕分开管理

图表留痕至少包括：

1. 更新时间
2. 新增或修正了哪个时间点的数据
3. 核心变化摘要
4. 是否触发观点更新

## 9. 页面交互建议

### 9.1 初稿

建议采用纵向结构：

1. 顶部操作条
2. 自动摘要
3. 初稿卡片列表
4. 信息源区

### 9.2 深度

建议采用折叠式纵向卡片墙：

1. 顶部工具条
2. 深度卡片列表
3. 卡片折叠态预览
4. 卡片展开详情
5. 区块级编辑
6. 版本记录抽屉

### 9.3 待吸收

建议采用“按来源折叠 + 列表”结构：

1. 顶部筛选
2. 研报
3. 附件
4. 纪要
5. 专家会

每组可折叠，组内按时间倒序。

### 9.5 未分类检查页

建议采用“列表 + 批量操作条”结构：

1. 顶部批量操作条
2. 资料列表
3. 每条资料的目标卡片与目标区块下拉
4. 批量分发后直接写入对应卡片候选池

### 9.4 生成报告

建议采用：

1. 输入源选择卡
2. 报告风格选择卡
3. 生成按钮区
4. 输出结果区

## 10. 一期边界

本轮只定义概览工作台的结构，不扩展到所有框架模块。

一期必须完成：

1. 行业概览与个股概览统一为 4 个 tab
2. `初稿 / 深度 / 待吸收 / 生成报告` 的页面骨架
3. 深度卡片模型
4. 候选吸收与对比机制骨架
5. 版本留痕骨架
6. 附件、纪要等入口接入 `待吸收`
7. 深度卡片折叠态与区块级编辑骨架
8. 多资料导入 -> 未分类检查页 -> 候选池 的流程骨架
9. 数据图表块自动更新后生成候选观点的接口骨架

一期可以只做骨架或简化实现的部分：

1. 局部段落级 diff 可先做文本级对比
2. 自动命中卡片逻辑可先采用关键词与模块映射
3. 图表自动重建先保留接口，不要求一步到位
4. 多资料导入的一次性批量解析可先支持基础文本与图片识别，不要求一步到位覆盖所有复杂格式

## 11. 风险与约束

1. 若自动提炼质量一般，`初稿` 可能较粗糙，因此不能与 `深度` 共用同一内容位。
2. 若没有 `待吸收` 缓冲区，新增材料会不断污染主版本。
3. 若没有版本留痕，后续无法复盘判断变化原因。
4. 若把手动附件与自动来源混在同一个信息源区，会导致来源语义混乱。

## 12. 验收标准

满足以下条件则视为本设计落地正确：

1. 用户能在行业概览、个股概览中看到 4 个顶部 tab。
2. 初稿可持续更新，但不会自动覆盖深度。
3. 附件、纪要、专家会等新增材料会先进入待吸收。
4. 待吸收按 `研报 / 附件 / 纪要 / 专家会` 分组。
5. 命中已有卡片时，默认先对比，再由用户决定。
6. 吸收后能保留版本前后差异记录。
7. 生成报告默认以深度内容为主输入。
8. 深度卡片默认折叠，只显示前 2-3 行正文预览。
9. 深度卡片各区块单独编辑、单独保存，不允许阅读态直接改写。
10. 多篇资料导入必须先进入未分类检查页，再批量或逐条分发到候选池。
11. 数据图表块自动更新后，既留痕又生成待吸收候选观点。
