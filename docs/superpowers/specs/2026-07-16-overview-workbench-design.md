# 行业/个股概览工作台设计稿

日期：2026-07-16

## 1. 目标

为 `框架沉淀 -> 行业中心` 与 `框架沉淀 -> 个股中心` 的 `行业概览 / 个股概览` 建立统一的工作台结构，使其不再只是单次生成的静态内容，而是成为一个可持续迭代的研究底座。

该工作台要同时满足四个目标：

1. 能通过“提取研报”快速生成一个可用的初始框架。
2. 能把用户后续投喂的研报、附件、纪要、专家会内容沉淀为长期版本。
3. 能让新增材料先进入缓冲区，而不是直接覆盖用户的主判断。
4. 能以正式主版本为基础，一键生成高质量行业报告或个股报告。

## 2. 适用范围

本设计同时适用于两类对象：

1. 行业中心中的 `行业概览`
2. 个股中心中的 `个股概览`

两者共用同一套页面结构、数据模型、候选吸收机制和版本留痕机制，仅在默认卡片模板、报告文案和引用来源名称上有所区分。

## 3. 页面结构

`行业概览` 与 `个股概览` 顶部统一采用 4 个 tab 切换：

1. `初稿`
2. `深度`
3. `待吸收`
4. `生成报告`

这 4 个 tab 的职责如下。

### 3.1 初稿

`初稿` 是自动生成区，用于承接“提取研报”或后续自动抓取资料后的第一版框架。

定位：

1. 快速起框架
2. 展示自动抽取结果
3. 持续刷新，但不直接影响用户主版本

页面内容：

1. 顶部工具区
   - `提取研报`
   - `重新生成初稿`
   - `查看自动信息源`
2. 初稿摘要区
   - 最近一次生成时间
   - 本次读取资料数量
   - 本次命中的关键词/主题
3. 初稿内容区
   - 以卡片形式展示自动生成的模块
   - 每张卡片对应一个概览模块，如市场规模、产业链、竞争格局等
4. 卡片操作
   - `加入待吸收`
   - `忽略`
   - `查看来源`

说明：

1. `初稿` 允许持续更新。
2. `初稿` 不得直接改写 `深度`。
3. 每次更新初稿后，仅形成新的候选增量，不自动同步到主版本。

### 3.2 深度

`深度` 是用户的正式主版本，采用卡片库而不是长文模式。

定位：

1. 承载用户长期维护的正式研究框架
2. 允许 AI 参与整理，但不允许自动覆盖
3. 作为最终生成报告的主输入

页面内容：

1. 顶部工具区
   - `新增卡片`
   - `调整排序`
   - `查看版本记录`
2. 深度卡片区
   - 每张卡片单独展示
   - 支持编辑标题、正文、图表说明、观点结论
3. 卡片附属区
   - 来源引用
   - 最近更新时间
   - 最近一次吸收来源
   - 版本数量

默认卡片模板：

行业概览默认建议包含但不限于：

1. 市场规模与需求
2. 产业链结构
3. 竞争格局
4. 核心公司
5. 行业驱动因素
6. 催化剂
7. 风险点
8. 自定义卡片

个股概览默认建议包含但不限于：

1. 公司定位与业务结构
2. 成长逻辑
3. 竞争优势
4. 管理层与治理
5. 财务与经营抓手
6. 催化剂
7. 风险点
8. 自定义卡片

说明：

1. `深度` 的每张卡片都是正式内容。
2. 用户可以手动编辑，后续也可接入 AI 辅助润色。
3. 任何自动更新内容都不能直接进入正式卡片。

### 3.3 待吸收

`待吸收` 是所有新增信息的缓冲区，是本设计的核心。

定位：

1. 承接新增材料的结构化提炼结果
2. 让用户在吸收前先看差异
3. 避免初稿、附件、纪要等内容直接污染主版本

页面内容：

1. 顶部筛选区
   - 按来源筛选
   - 按日期筛选
   - 按状态筛选
2. 候选分组区
   - `研报`
   - `附件`
   - `纪要`
   - `专家会`
3. 候选列表
   - 每条候选项显示标题、来源、命中卡片、摘要、生成时间
4. 候选操作
   - `对比后决定`
   - `忽略`
   - `标记稍后处理`

来源约束：

1. 自动提取的公开研报进入 `研报`
2. 用户在附件链接中上传或粘贴的新资料，解析后进入 `附件`
3. 调研纪要解析结果进入 `纪要`
4. 专家会纪要解析结果进入 `专家会`

候选状态：

1. `未处理`
2. `已吸收`
3. `已忽略`
4. `稍后处理`

### 3.4 生成报告

`生成报告` 是输出页，不承担编辑和沉淀职责。

定位：

1. 将概览工作台中的成熟内容整理为报告
2. 支持行业报告、个股报告的统一生成
3. 支持选择输入源范围

页面内容：

1. 报告类型
   - 行业报告
   - 个股报告
2. 输入源选择
   - `仅深度`
   - `深度 + 待吸收`
   - `初稿 + 深度`
3. 报告风格选择
   - 深度版
   - 快速版
   - 汇报版
4. 输出动作
   - `生成报告`
   - `生成图片`
   - `复制摘要`

说明：

1. 默认推荐输入源为 `仅深度`。
2. 若用户选择包含 `待吸收`，应在生成前给出提示，说明报告可能包含未正式确认的信息。

## 4. 深度卡片数据模型

每张深度卡片都应具备以下 4 层结构：

1. `正式内容`
2. `候选变更`
3. `版本记录`
4. `来源引用`

### 4.1 正式内容

正式内容是当前可见、可编辑、可用于生成报告的主版本。

字段建议：

1. `id`
2. `scope_type`：`sector` 或 `stock`
3. `scope_id`
4. `title`
5. `body`
6. `chart_blocks`
7. `status`
8. `updated_at`

### 4.2 候选变更

候选变更来自 `待吸收`，但命中的是某张已有卡片。

字段建议：

1. `candidate_id`
2. `source_type`
3. `source_title`
4. `source_url`
5. `proposed_patch`
6. `matched_card_id`
7. `created_at`
8. `state`

### 4.3 版本记录

每次用户确认吸收某条候选后，都要生成一条版本留痕。

字段建议：

1. `version_id`
2. `card_id`
3. `action_type`
4. `source_type`
5. `source_title`
6. `before_snapshot`
7. `after_snapshot`
8. `change_summary`
9. `created_at`

### 4.4 来源引用

来源引用用于说明一张卡片当前判断背后的材料来源，不等同于附件区展示。

来源只展示自动提取来源与后续可接入来源，例如：

1. 东财研报
2. AlphaEngine
3. 公开纪要接口
4. 专家会接口

用户手动上传的文件与笔记链接继续保留在 `附件链接` 模块，不在这里直接展示为信息源接口。

## 5. 候选吸收机制

候选项进入 `待吸收` 后，不允许直接写入 `深度`。

标准流程：

1. 新材料进入系统
2. 系统提炼出候选项
3. 候选项按来源进入 `待吸收`
4. 若命中已有卡片，则进入 `对比后决定`
5. 用户确认后，系统再写入正式卡片并保留版本记录

用户确认动作只支持以下几类：

1. `替换原文`
2. `追加为补充段`
3. `仅更新局部`
4. `忽略`

不提供自动覆盖。

## 6. 对比视图设计

当候选项命中已有卡片时，系统默认进入 `对比后再决定` 模式。

交互要求：

1. 左侧显示 `原有版本`
2. 右侧显示 `候选新内容`
3. 中间高亮差异
   - 新增内容
   - 删除内容
   - 改写内容
4. 底部显示操作按钮
   - `替换原文`
   - `追加补充`
   - `仅更新选中段落`
   - `忽略`

目标：

1. 用户能清楚知道改了什么
2. 用户能基于差异做判断
3. 吸收后能完整留痕

## 7. 版本留痕设计

版本留痕用于支持未来复盘观点演化。

每条版本记录至少展示：

1. 日期时间
2. 来源类别
3. 来源标题
4. 命中的卡片
5. 改动摘要
6. `查看变更前后`

复盘时，用户应能看到：

1. 原来怎么写
2. 后来因什么材料做了修改
3. 具体改动点是什么

## 8. 与现有模块的关系

### 8.1 附件链接

`附件链接` 保持为手动资料库，仅展示用户主动上传或粘贴的资料。

新增要求：

1. 新增附件进入资料库后，可以触发解析
2. 解析结果不直接进入 `深度`
3. 解析结果进入 `待吸收 -> 附件`

### 8.2 调研纪要 / 行业纪要 / 跟踪点评

这些内容依旧保留在行业中心、个股中心的原模块中。

新增要求：

1. 新写入的纪要或点评可以触发候选提炼
2. 候选结果进入 `待吸收`
3. 若命中某张概览卡片，则支持差异对比吸收

### 8.3 信息源接口

`行业概览 / 个股概览` 下方保留与 `投研资讯` 类似的信息源展示与扩展接口。

但只展示自动提取来源和未来的外部接口来源，不展示用户手动投喂资料。

## 9. 页面交互建议

### 9.1 初稿

建议采用纵向结构：

1. 顶部操作条
2. 自动摘要
3. 初稿卡片列表
4. 信息源区

### 9.2 深度

建议采用纵向卡片墙：

1. 顶部工具条
2. 深度卡片列表
3. 卡片展开详情
4. 版本记录抽屉

### 9.3 待吸收

建议采用“按来源折叠 + 列表”结构：

1. 顶部筛选
2. 研报
3. 附件
4. 纪要
5. 专家会

每组可折叠，组内按时间倒序。

### 9.4 生成报告

建议采用：

1. 输入源选择卡
2. 报告风格选择卡
3. 生成按钮区
4. 输出结果区

## 10. 一期边界

本轮只定义概览工作台的结构，不扩展到所有框架模块。

一期必须完成：

1. 行业概览与个股概览统一为 4 个 tab
2. `初稿 / 深度 / 待吸收 / 生成报告` 的页面骨架
3. 深度卡片模型
4. 候选吸收与对比机制骨架
5. 版本留痕骨架
6. 附件、纪要等入口接入 `待吸收`

一期可以只做骨架或简化实现的部分：

1. 局部段落级 diff 可先做文本级对比
2. 自动命中卡片逻辑可先采用关键词与模块映射
3. 图表自动重建先保留接口，不要求一步到位

## 11. 风险与约束

1. 若自动提炼质量一般，`初稿` 可能较粗糙，因此不能与 `深度` 共用同一内容位。
2. 若没有 `待吸收` 缓冲区，新增材料会不断污染主版本。
3. 若没有版本留痕，后续无法复盘判断变化原因。
4. 若把手动附件与自动来源混在同一个信息源区，会导致来源语义混乱。

## 12. 验收标准

满足以下条件则视为本设计落地正确：

1. 用户能在行业概览、个股概览中看到 4 个顶部 tab。
2. 初稿可持续更新，但不会自动覆盖深度。
3. 附件、纪要、专家会等新增材料会先进入待吸收。
4. 待吸收按 `研报 / 附件 / 纪要 / 专家会` 分组。
5. 命中已有卡片时，默认先对比，再由用户决定。
6. 吸收后能保留版本前后差异记录。
7. 生成报告默认以深度内容为主输入。
